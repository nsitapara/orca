# Pilot hooks into upstream Orca

Every change Pilot makes to an upstream file is listed here (D24). Each one is an import plus one call, one JSX element, or one config line. The logic lives in `src/packages/pilot/`. `node src/packages/pilot/scripts/hook-guard.mjs` checks that every row's file still contains its Match text, and that no other upstream file differs from `upstream/main`. After an upstream sync, a failing row names the file to fix.

Which hooks were added for "Show all tabs in Activity", and why:

- `activity-tabs-row-type`, `activity-tabs-rows`, `activity-tabs-row-key`, `activity-tabs-row`, `activity-tabs-header-count` and `activity-tabs-count`: the option is a filter on Activity's one list, not a second section (Nish, 2026-10-17). Tabs are rows in the agents' groups, so they share the scroll, the sticky headers, collapse and Group by. The tabs ride on each group object through a WeakMap in `activity-tabs-rows.ts`, so upstream's group type is unchanged and every hook returns upstream's value until a group carries tabs.
- `activity-tabs-group-header`, `activity-tabs-nest` and `activity-tabs-thread-icons`: grouped by worktree, a group's sessions were hard to tell from the next worktree's, and a row's first icon was its state, not its agent (Nish, 2026-10-17). Each hook wraps upstream's own element and renders it unchanged until Pilot attaches; the nest sits inside the row's spacer because that spacer is the context menu's `asChild` trigger. `activity-tabs-thread-icons` was retired on 2026-10-27 for `activity-tabs-thread-row`.

Which hooks were extended for nested throwaways, and why:

- `activity-tabs-threads`, `activity-tabs-group-header` and `activity-tabs-nest`: a Pilot run's throwaway has a detached HEAD, so it showed as its own group named after the repo, reading as the main checkout, while the worktree it tested sat under Inactive (Nish, 2026-10-20). When a run gets a throwaway, Pilot names it for its job and commit and sets its parent to the item's worktree through the runtime's worktree metadata (what `orca worktree set` calls). Activity reads that lineage with the Projects sidebar's own rules (`worktree-nest-parent.ts`): grouped by worktree, a child's group follows its parent's, a parent counts its children's sessions and leaves Inactive while one runs, and the child groups ride on the parent's group object through a WeakMap, as the tabs do.

Which hooks were added for "Hide terminals", and why:

- `activity-tabs-filter-menu` and `activity-tabs-filter-count`: with "Show all tabs" on, plain terminals (a dev server, a stack) crowd the agent sessions (Nish, 2026-10-19). "Hide terminals" is a filter, so it sits in the Filters section with upstream's Hide items and counts toward the options badge. It is offered only while "Show all tabs" is on, since only then does the list hold terminals. A terminal counts as an agent by `resolveOpenTabOccupantAgent`, the tab strip's identity rules that tab search already uses. Both return upstream's value until Pilot attaches: the item renders nothing and the count is 0.

Which hooks were extended for "Hide automation runs", and why:

- `activity-tabs-filter-menu`, `activity-tabs-filter-count` and `activity-tabs-threads`: Pilot's automation sessions fill Activity, and one may not always want to see them (Nish, 2026-10-20). It is a filter like "Hide terminals", offered whenever Pilot is attached since agent sessions always list. A row counts as an automation run when a Pilot step ran in its tab: the step table records each step's pane key (`<tabId>:<leafId>`), and `pilot.runs.automationTabs` answers for the tab ids it is given, asked of the Pilot on the row's host. A "no" is asked again for a minute, because a step records its pane only after its tab opens; a host that refuses (unreachable, or a build without the method) leaves its rows shown.

Which hooks were added for links and stack ports, and why:

- `activity-tabs-footer-label`: grouped by worktree, a row's footer repeated the worktree name its header shows (Nish, 2026-10-19). The wrapper reads the row's group from a context `ActivityTabsNest` provides and, under a worktree, shows the MR and Linear chips Cove shows. Each worktree header fetches them once (the hover card's own lifecycle effects, 60 s cache), so rows only read the caches. Grouped otherwise, or before Pilot attaches, upstream's name renders. Later the same day (2026-10-20) the chips moved up to the header, once per worktree, so the footer under a worktree shows no name and no chips. Retired on 2026-10-27: the one-line row (`activity-tabs-thread-row`) has no footer.
- `activity-tabs-hover-card`: the card led with the session summary its row already shows, and its links and ports came last (Nish, 2026-10-19). Reordering upstream's JSX would be more than a hook, so Pilot renders its own card from upstream's exported sections and the same data hooks (`use-hover-card-details.ts` mirrors the wiring), and upstream's card renders until Pilot attaches. The stack's ports come from the worktree's `.env.ports`, read through `readRuntimeFileContent`. An SSH worktree's file can't be read from the desktop, so its card keeps upstream's Live Ports list. On 2026-10-20 every section about the worktree left the card: hovering any session showed the same worktree card (Nish). The worktree's MR, Linear issue and ports are chips under its header (`WorktreeLinkStrip`; ports open a menu listing the stack's ports), and the card shows only the session.

Which hooks changed for folding worktrees and one-line rows, and why:

- `activity-tabs-group-header`, `activity-tabs-threads` and `activity-machines-list`: a worktree's sessions and its child worktrees couldn't be folded (Nish, 2026-10-27).
